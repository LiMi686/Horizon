## [Executable as SQLite Database: A Novel Self-Describing Binary Format](https://fzakaria.com/2026/08/23/your-executable-is-a-sqlite-database) ⭐️ 8.0/10

Farid Zakaria's article demonstrates a technique to embed a SQLite database directly into an executable file, leveraging the SQLite file format's application ID field to make the binary both runnable and queryable. This approach allows the executable to serve as its own metadata store, enabling introspection and manipulation of the binary's contents using SQL queries. This concept could revolutionize software distribution and data management by enabling self-describing executables that carry structured metadata, configuration, or even assets within the binary itself. It opens up possibilities for more efficient packaging, easier debugging, and dynamic inspection of executables, potentially impacting developers, security analysts, and system administrators. The technique sets the SQLite file format's 4-byte application ID (located 68 bytes into the file) to 'SELF', allowing the file to be recognized as both an executable and a SQLite database. The article also discusses using SQLite virtual tables to 'mount' filesystems or other data sources as queryable databases, and notes that SQLite's dynamic linking is compatible with ELF dynamic linking, suggesting potential for replacing AppImages with a more efficient format.

hackernews · setheron · Aug 24, 04:48 · [Discussion](https://news.ycombinator.com/item?id=49415271)

**Background**: The Executable and Linkable Format (ELF) is a common standard file format for executables, object code, shared libraries, and core dumps on Unix-like systems. ELF files are composed of sections and segments, but the format is terse and lacks a self-describing schema, making modifications difficult. SQLite is a lightweight, file-based relational database that stores data in a single file, and its format includes an application ID field that can be used for custom identification. By combining these, the article proposes a way to make executables self-describing and introspectable.

## [Monotone Corruptions Break Multiclass and Partial Concept Learning](https://arxiv.org/abs/2608.20480) ⭐️ 8.0/10

This paper demonstrates that monotone adversarial corruptions, which only add correctly labeled but adversarial examples, cause dramatically worse learning guarantees in multiclass classification and partial binary concept classes compared to binary classification. Specifically, the authors exhibit a learnable multiclass problem with DS dimension 2 that becomes unlearnable under a monotone adversary inserting a linear number of points, and an analogous result for partial binary concept classes. This result reveals that monotone adversaries are significantly more powerful in broader learning settings, challenging the robustness of standard PAC learners beyond binary classification. It addresses an open problem and has implications for designing robust algorithms in multiclass and partial concept scenarios, which are common in real-world applications. The impossibility results are achieved by an adaptive adversary that can view the original i.i.d. training set S and insert b < ∞ corrupted points; in the multiclass example, only b = n points are needed. The paper also proves that every class remains learnable when the number of adaptive additions is o(n), which is tight, and that classic O(d_DS/n) error rates remain achievable against adversaries with constant budget, semi-adaptive adversaries, and oblivious adversaries.

rss · arXiv - Data Science & Statistics · Aug 24, 04:00

**Background**: The classic PAC model assumes training data is i.i.d., and optimal learners exploit this assumption. Larsen et al. (2026) introduced a model of monotone adversarial corruptions where an adversary adds correctly labeled but adversarial examples to the training set, showing that binary learners suffer increased error rates. Mehrotra (2026) proved the logarithmic factor is necessary for binary classification, but left open the consequences for multiclass and partial concept classes. Partial concept classes allow concepts to be undefined on some inputs, modeling tasks with special data properties.
