## [Activation Patching Flaw: Hidden Interaction Effects Distort Causal Attributions](https://arxiv.org/abs/2606.27510) ⭐️ 9.0/10

A new paper reveals that activation patching, a key method in mechanistic interpretability, conflates direct causal effects with interaction effects (INT), leading to potential misattributions of component importance. The authors demonstrate this flaw in the GPT-2 IOI circuit, showing that INT can either hide or inflate the apparent importance of components. This finding challenges the reliability of activation patching, a widely used tool for understanding neural network internals, and could reshape how researchers interpret causal attributions in mechanistic interpretability. It highlights the need for careful analysis of interaction effects when drawing conclusions about component roles. The paper proves that INT scales with the distance between clean and patched activations, is negligible when the model is locally affine, and decomposes into pairwise and higher-order group interactions. The authors argue that INT should be used as a diagnostic rather than eliminated, as it signals when causal conclusions are prompt-dependent.

rss · arXiv - Machine Learning · Jun 29, 04:00

**Background**: Activation patching is a causal intervention technique in mechanistic interpretability that swaps internal activations to identify which components are causally responsible for a specific behavior. It estimates the natural indirect effect (NIE) from causal mediation analysis, but this paper shows that NIE also captures interaction effects, not just the direct causal pathway through the component.

The WATaBoy project demonstrates that JIT-compiling Game Boy emulator instructions to WebAssembly (WASM) outperforms a native interpreter by exploiting the browser's JIT compilation capabilities. This approach creatively bypasses iOS JIT restrictions by running in a browser context, enabling high-performance emulation on platforms like iOS where native JIT is prohibited. It also highlights the potential of WASM as a compilation target for emulation. The project uses a custom JIT compiler that translates Game Boy Z80-like instructions into WASM bytecode, which is then further JIT-compiled by the browser's WASM engine. Performance comparisons show the WASM JIT approach significantly outperforms a native interpreter, though Firefox was found to be 25% slower than Chrome and Safari.

In emulation, interpreters execute each instruction one by one, incurring high overhead, while JIT compilers translate emulated code into native code for better performance. WebAssembly is a low-level binary format that runs efficiently in browsers, and browsers themselves use JIT to further optimize WASM execution.

## [Deep Dive: CUDA Kernel Launch Path from CPU to GPU](https://fergusfinn.com/blog/what-happens-when-you-run-a-gpu-kernel/) ⭐️ 8.0/10

A technical blog post by Fergus Finn explains the complete process of launching a CUDA kernel, from the host-side syntax to GPU submission, covering doorbell registers and queue management descriptors (QMDs). This deep-dive bridges a critical gap in understanding CUDA by detailing the CPU-to-driver-to-GPU path, which is often glossed over in higher-level tutorials. It helps systems programmers and GPU engineers optimize kernel launch latency and debug performance issues. The post explains that the CUDA runtime constructs a control word and a QMD, writes them to a submission queue, then rings a doorbell register on the GPU to signal new work. The GPU's work scheduler then reads the QMD and executes the kernel.

hackernews · mezark · Jun 29, 13:11 · [Discussion](https://news.ycombinator.com/item?id=48718863)

**Background**: CUDA is NVIDIA's parallel computing platform that allows developers to run code on GPUs. A kernel launch involves the CPU preparing a command buffer and notifying the GPU via a doorbell mechanism. The queue management descriptor (QMD) contains metadata like grid dimensions and kernel function pointer.
