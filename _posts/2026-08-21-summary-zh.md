## [意外发现：配置错误的 E.164 ARPA 域名暴露军方电话呼叫](https://lina.sh/blog/hijacking-e164-arpa) ⭐️ 8.0/10

一名安全研究人员意外发现，数十万通打给军事基地的电话被路由到一个配置错误的 E.164 ARPA 域名，暴露了电话基础设施中的重大缺陷。该事件已被报告并得到处理，但研究人员未获得奖励。 这凸显了全球电话路由系统中一个关键的安全和隐私漏洞，可能导致敏感的军事通信被拦截或错误路由。它强调了在 ENUM 和 E.164 ARPA 等基础设施协议中需要更好的监督和安全措施。 该配置错误涉及 E.164 ARPA 域名，该域名用于 DNS 中的 ENUM（电话号码映射）。研究人员未设置 SIP 服务器来测试呼叫终止，但问题的规模表明此类域名的管理存在系统性问题。

hackernews · gavide · Aug 21, 13:11 · [社区讨论](https://news.ycombinator.com/item?id=49387570)

**背景**: E.164 ARPA 是 DNS 中的一个特殊用途域名，用于 ENUM，它将电话号码映射到 URI，以便在 IP 网络上路由呼叫。ENUM 旨在促进 VoIP 互操作性，但公开采用有限，私有实现用于号码可移植性。此类基础设施的配置错误可能导致敏感呼叫被意外路由。

## [Agent Substrate：面向 AI 代理的高密度运行时](https://github.com/agent-substrate/substrate) ⭐️ 8.0/10

谷歌开源了 Agent Substrate，这是一个面向大规模 AI 代理部署的 Kubernetes 原生运行时，提供亚秒级的挂起/恢复操作以及将代理高密度复用到底层共享基础设施的能力。它支持包括 microVM 和 gVisor 在内的多种沙箱技术。 Agent Substrate 解决了扩展 AI 代理时的一个关键瓶颈：高效的沙箱生命周期管理。通过实现重度超订（例如，8 个 Pod 上运行 250 个 actor），它可以显著降低基础设施成本并提高代理工作负载的资源利用率，从而使整个 AI/ML 和系统工程社区受益。 Agent Substrate 并非谷歌官方支持的产品，也不符合谷歌开源软件漏洞奖励计划的资格。它利用 Kubernetes 进行基础设施供应和工作节点生命周期管理，同时提供针对代理的调度以实现更低延迟。该项目与框架无关，通过 gVisor 管理标准 OCI 容器。

rss · GitHub Trending - Daily (All) · Aug 21, 22:16

**背景**: AI 代理通常大部分时间处于空闲状态，因此为每个代理分配完整的虚拟机或容器效率低下。像 microVM（例如 Firecracker）和 gVisor 这样的沙箱技术提供了隔离，但通常有冷启动开销。Agent Substrate 利用挂起/恢复和状态快照将许多代理多路复用到更少的工作节点上，从而降低成本并提高密度。

rss · GitHub Trending - Daily (All) · Aug 21, 22:16

**背景**: AI 代理通常难以管理上下文，包括记忆、知识检索和技能。传统方法使用向量存储进行检索增强生成（RAG），但 OpenViking 提出了一种文件系统范式，代理可以使用 ls、tree 和 find 等命令浏览其上下文。这种方法旨在使上下文更加透明和可调试，符合代理上下文工程的趋势。
