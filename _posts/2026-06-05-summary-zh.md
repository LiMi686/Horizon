## [微软开源 pg_durable，为 PostgreSQL 提供持久执行能力](https://github.com/microsoft/pg_durable) ⭐️ 8.0/10

微软开源了 pg_durable，这是一个 PostgreSQL 扩展，利用 pgrx 和 Rust 库 duroxide 构建，实现了数据库内的持久执行工作流编排。 这直接将持久执行能力引入 PostgreSQL，减少了对 Temporal 等外部服务的依赖，简化了 Postgres 用户的工作流可靠性保障。 pg_durable 完全在 PostgreSQL 服务器内部作为后台工作进程运行，提供 SQL DSL 用于定义函数图，并在故障后确保确定性重放。

**背景**: 持久执行是一种编程范式，能自动持久化工作流进度以应对崩溃和重启。传统上，这需要 Temporal 或 Azure Durable Functions 等外部平台。pg_durable 将这一能力直接嵌入 PostgreSQL，允许在数据库内部定义和执行工作流。

## [Claude 生成的代码可能在 rsync 中引入错误](https://alexispurslane.github.io/rsync-analysis/) ⭐️ 8.0/10

一项对 rsync 提交的分析表明，使用 Claude 编写的代码可能引入了错误，特别是强制用 calloc 替代 malloc，从而降低了性能和正确性。分析指出一个特定提交无条件地将 malloc 替换为 calloc，该提交后来被还原。 此案例凸显了盲目信任 LLM 生成代码的风险，尤其是在像 rsync 这样的关键系统工具中。它引发了关于如何在软件工程中负责任地集成 AI 辅助而不损害代码质量的讨论。 该分析使用自定义方法将错误归因于提交，但批评者指出它没有控制提交复杂性、安全强度或错误严重性。仅识别出两个 Claude 共同编写的提交，这引发了关于统计显著性的质疑。

hackernews · logicprog · Jun 5, 12:43 · [社区讨论](https://news.ycombinator.com/item?id=48411635)

**背景**: rsync 是一个广泛使用的文件同步工具，用 C 语言编写。函数 malloc 和 calloc 都分配内存，但 calloc 还会将内存初始化为零，对于大块分配可能更慢。无条件地用 calloc 替换 malloc 可能会引入性能回归，并通过掩盖未初始化内存问题来隐藏错误。
